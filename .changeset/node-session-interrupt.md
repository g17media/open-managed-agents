`user.interrupt` now actually stops the in-flight turn on the self-host Node host, and the event is persisted. `SessionStateMachine` mints an `AbortController` per turn, hands its signal to the shell through `buildHarnessContext({ abortSignal })` — where `NodeHarnessRuntime` exposes it as `HarnessRuntime.abortSignal`, which the default loop already passes to `streamText` — and exposes an `interrupt()` that `SessionRegistry.interrupt` was already probing for. An aborted turn ends with the terminal `session.status_idle` and NO `session.error` (a user-initiated stop is not a failure), matching the CF `SessionDO`; outputs are promoted on the success path only. `NodeSessionRouter.appendEvent` persists and publishes the `user.interrupt` event before aborting, so it appears in the trajectory (`eventsToMessages` ignores it, so model context is unchanged). Previously the route returned `202 {"interrupted":true}` while the turn kept calling tools and burning tokens.

Note for eval consumers: an interrupted turn still ends with `session.status_idle` (no `session.error`), and that event lands in the log *after* `user.interrupt`. `deriveOutcome` in `packages/eval-core/src/trajectory/build.ts` scans events newest-first and returns on the first match, so it hits `session.status_idle` before the preceding `user.interrupt` and scores the trajectory `"success"` — not `"interrupted"` — unless a caller explicitly checks for a `user.interrupt` event earlier in the log.

**Follow-up (turn lifecycle).** `SessionStateMachine` now tracks live turns in one `Map<turnId, AbortController>` instead of a single `activeTurnId` slot beside a `Set` of controllers. Node's dispatch starts a turn per `user.message` with no in-flight check, so several can run at once; with the old pair the second turn overwrote the slot and the first turn finishing cleared it, which marked the session idle — and published the terminal `session.status_idle` — while the second turn was still streaming. `session.status_idle` is now emitted once, by the last turn out, and that turn emits it **whatever its own outcome**: the sentence above ("an aborted turn ends with the terminal `session.status_idle`") is now more precisely "the last turn out ends the session", including the turn that threw or that failed before `beginTurn`. Gating it on success left a session with no terminal event at all when a completed turn had suppressed its own idle for a sibling that then failed, hanging that first turn's `/messages` stream for the life of the process. Registration and `beginTurn` also moved inside the turn's `try`, so a `beginTurn` rejection no longer leaves a phantom in-flight turn, and `destroy()` ends every turn it was holding rather than one.

`NodeSessionRouter.appendEvent`'s `user.interrupt` branch publishes the row it appended — its own seq, then that single row — instead of re-reading the whole event log and publishing the last row, which raced the aborted turn's own terminal event and published `session.status_idle` under the interrupt's name. The registry abort moved into a `finally`, so no failure in the persist/publish block can strand a turn.

Eval note, extending the one above: `session.status_idle` now also follows `session.error` when the failing turn is the last one out, so a newest-first `deriveOutcome` scan hits `status_idle` before that error too.
