### Tool execution and media results

`DefaultHarness` and `PiHarness` execute tools from one model step sequentially
by default. Calls run in order, so a script run sees an edit made by an earlier
call. An ordinary tool error is returned to the model and later calls still run;
interrupting the turn stops queued calls. Client tools and calls awaiting
permission still require the client's response; sequential execution does not
make them barriers for other executable calls.

Independent tools can opt into concurrent execution per agent:

```json
{ "metadata": { "tool_execution": "parallel" } }
```

Only the exact value `"parallel"` enables concurrency. Omitting the key, setting
`"sequential"`, or any other value keeps sequential execution. Parallel calls
may finish out of order, but their results reach the next model request in call
order. A single tool call requires no extra batching delay in either mode.
This option applies to these host harnesses, not third-party ACP agent loops.

The `read` tool returns images as `image-data` and documents as `file-data`.
The default harness's Anthropic adapter sends them as image and document blocks,
respectively, including when replaying persisted history. Pi accepts inline
images from `image-data`, image `file-data`, and AI SDK `file` parts containing
base64 strings, byte arrays, or `{ "type": "data", "data": "<base64>" }`.
MIME types and the order of text and image parts are preserved. Pi represents
URL-backed files and non-image files such as PDFs with text omission notices.
Pi tool results retain the shared binary budget from the tool-result limits:
`max(40 × TOOL_RESULT_MAX_CHARS, 2,000,000)` base64 characters per result.
Images beyond that budget are omitted whole with a notice, never truncated.

### Default harness context safety

The default harness checks context size before every model request, including
requests after tool execution within the same turn. It starts summarizing at
75% of the input window by default (`metadata.compaction_trigger_fraction`).
The model card's input budget takes precedence over model-name heuristics.
Stored cards configure this through `pi_config.contextWindow`, exposed as
`max_input_tokens` by `/v1/models`. Missing limits fall back to model-name
heuristics, capped by the runtime provider's capacity hint (128,000 tokens
for an unknown custom Pi model).

If the estimated history already exceeds the window, the harness first
replaces large older tool results with
`[tool result elided during compaction: N chars; re-run the tool if needed]`.
It removes the largest results first, oldest first when sizes tie, preserving
a recent tail aligned to a user message. The tail budget scales down for small
model windows. The harness then attempts normal summarization if it fits.
A context-length failure from the summarizer also triggers this structural
pass. Elisions are persisted in `agent.thread_context_compacted` metadata;
the original event log remains intact, while replay uses the smaller view.

An empty `finish_reason=length` response or a provider context-length rejection
triggers an emergency pass and one request retry. If it fails again for context length, the error states that the
context exceeded the model window and the session must be reset. Histories
dominated by protected messages or user content may still require a reset.

The estimate uses roughly four serialized message characters per token; it
is not provider tokenization or a billing count. Text, JSON and binary content
can differ substantially from actual token usage, so the trigger leaves
headroom and the retry handles provider-reported overflows.

### Pi harness compaction

`harness: "pi"` always enables harness-owned context compaction. These optional
metadata keys select and tune the built-in policy:

```json
{
  "harness": "pi",
  "metadata": {
    "compaction_strategy": "cc-style",
    "compaction_trigger_fraction": 0.75,
    "compaction_max_summary_tokens": 2000,
    "compaction_summary_prompt": "Optional replacement summary prompt"
  }
}
```

`compaction_strategy` accepts `cc-style` (default), `opencode-style`, or
`summarize`. Invalid names fall back to `cc-style`; there is intentionally no
`none` mode. All built-in policies use `pi-ai` without requesting reasoning.

- `cc-style` uses an isolated summary payload: a short summary-only system
  prompt, no tools, image placeholders instead of image bytes, and a separate
  compaction session id. This is the robust default and intentionally does not
  reuse the main agent's provider prefix cache.
- `opencode-style` has the same isolated payload boundary, with a structured
  Goal / Instructions / Discoveries / Accomplished / Files summary template.
- `summarize` is the explicit cache-aware strategy. It replays the main
  request's exact system prompt, tool declarations, message history, and session
  id, then appends the private compaction instruction. It deliberately leaves
  `toolChoice` unset because some provider adapters remove tools for
  `toolChoice: "none"`, which changes the cache prefix. `completeSimple` does
  not execute tools; a returned tool call rejects the compaction boundary.
  Prefix-caching providers can therefore reuse the warm conversation prefix.

Applications can replace the whole `PiCompactionPolicy` when constructing
`PiHarness`; OpenMA still owns the canonical boundary event, failure fallback,
and the single overflow retry. Every strategy replaces old history with a new
summary boundary, so the first main-model request after compaction is a new
prefix even when the summary call itself reused the old prefix.

### Model provider retries

The default harness retries transient provider and network failures inside the
running turn. On the Node host these settings come from the server environment;
custom hosts can supply them through the harness environment.

| Variable | Default | Meaning |
| --- | --- | --- |
| `OMA_MODEL_RETRY_ATTEMPTS` | `4` | Extra attempts after the initial attempt. Set `0` to disable. |
| `OMA_MODEL_RETRY_BACKOFF_MS` | `5000,15000,45000,90000` | Comma-separated delays in milliseconds, with ±20% jitter. The last delay repeats if more attempts are configured. |
| `OMA_MODEL_RETRY_MAX_WAIT_MS` | `300000` | Total outer backoff budget per turn in milliseconds, including `Retry-After`. Stops retrying if the next wait exceeds the remaining budget. |

A provider's `Retry-After` header or retry-after field overrides the schedule,
without jitter, capped at 120 seconds. Malformed configuration falls back to
the defaults. These attempts are in addition to the AI SDK's short request
retries. The harness rebuilds context from persisted session events, including
completed tool results, so it continues the turn after the failed request.
Failed-step partial assistant output and tool calls that never executed are
discarded from history. The wait budget excludes provider request durations
and the SDK's internal retry delays; it is not an overall turn deadline.
User interrupts cancel the wait immediately. No new wire event types are emitted.

Retryable failures include HTTP 408, 409, 429, 500, 502, 503, 504 and 529,
Anthropic `overloaded_error`, `rate_limit_error` and `api_error`, and connection
failures. Auth, billing, other listed client errors (400/401/402/403/404/413/422),
context overflow and silent stops do not consume this provider retry budget;
context overflow retains its separate emergency-compaction recovery.

### MCP server config

MCP text results in the default and Pi harnesses share the built-in tool limit: 50,000 characters by
default, configurable with `OMA_TOOL_RESULT_MAX_CHARS`. Both individual text
blocks and the combined text are bounded, with a visible
`...(truncated, total N chars)` suffix. The truncated form is persisted in the
event log and passed to the model; oversized duplicate `structuredContent`
is omitted. Binary blocks are kept whole within a separate overall budget
of `max(40 × text limit, 2,000,000)` characters. Blocks beyond that budget are
replaced by an omission notice.

Replay applies the same policy to older persisted tool results, including
errors, without rewriting their original events. Built-in text results
(including `read`, `glob`, `grep`, and `web_fetch`) are also capped after
formatting, so a tool's own length option cannot raise the deployment limit.
Confirmed MCP calls persist bounded native content blocks as well. The Pi
harness preserves MCP images and emits omission notices for audio or document
blobs its tool-result protocol cannot represent.

```ts
type McpServerConfig =
  | {
      name: string;                 // becomes the prefix: mcp__<name>__<tool>
      type: 'url';
      url: string;
      authorization_token?: string; // inline bearer (otherwise: matched vault credential)
    }
  | {
      name: string;
      type: 'stdio';
      command: string;              // executable path supplied by the Environment
      args?: string[];
      env?: Record<string, string>; // enters the sandbox; do not put standing credentials here
    };
```

`stdio` is the standard MCP/ACP process transport; there is no port or SSE path. It works when an external Worker or a harness running inside the sandbox owns the child process. Harness-out-of-sandbox runtimes reject it explicitly because they cannot own a process inside the sandbox. URL MCP discovery is bounded at 15 s per server; up to 20 servers per agent.

The Agent declaration is launch configuration, not installation configuration. The selected Environment must provide the executable and all of its runtime dependencies at the declared path, through its package configuration or custom image. Every OpenMA-managed base Environment includes Node.js/npm (and therefore `npx`) plus the uv toolchain (`uv`/`uvx`); provider adapters must launch the corresponding OpenMA image, template, or snapshot without changing that contract. OpenMA does not infer or install dependencies from `command`. Additional executables belong in the Environment package list or image. BYO images and external Workers are outside the base-image guarantee and must declare and supply their own runtime contents.

## Vault

A vault is a tenant-scoped credential bundle; credentials inside it are bound to MCP servers or sandbox CLIs.

```ts
interface Vault {
  id: string;
  tenant_id: string;
  name: string;
  created_at: string;
  updated_at: string;
  archived_at?: string;
}

// Credentials live in a separate table
type CredentialAuth =
  | { type: 'service_account_jwt'; mcp_server_url: string; client_email: string;
      private_key: string; private_key_id?: string; token_uri?: string; scopes: string;
      subject?: string; audience?: string }
  | { type: 'static_basic'; username: string; token: string; mcp_server_url: string }
  | { type: 'static_bearer'; token: string; mcp_server_url: string }
  | { type: 'mcp_oauth'; access_token: string; refresh_token?: string;
      token_endpoint?: string; expires_at?: string; mcp_server_url: string }
  | { type: 'cap_cli'; cli_id: string; token: string };  // e.g. cli_id: "gh", "glab", "aws"
```

Binding to a host happens via the credential, not the vault: a `service_account_jwt` / `static_basic` / `static_bearer` / `mcp_oauth` credential matches by parsing the request hostname against `mcp_server_url`; a `cap_cli` credential matches by `cli_id` lookup in the cap spec registry. Up to 20 credentials per vault. Tokens are AES-GCM-encrypted at rest under `PLATFORM_ROOT_SECRET` and never returned via the API once written.

### HTTP Basic credentials

Create `static_basic` through `POST /v1/vaults/:id/credentials` with
`auth: { type: "static_basic", mcp_server_url: "https://langfuse.example.com",
username: "YOUR_PUBLIC_KEY", token: "YOUR_SECRET_KEY" }`.
The `token` field stores the password; `username` must be nonempty and contain
no colon or control characters. The URL must use HTTP or HTTPS. Password bytes,
including whitespace and colons, are preserved and encoded as UTF-8.

Self-host `oma-vault` matches the URL's host (including a nondefault port) and
replaces the client's Authorization header with `Basic base64(username:token)`
on every path, including REST and OTLP ingestion. An exact Basic-username
`handle` match on a bearer/CLI credential wins. Otherwise, incoming Basic auth
prefers `static_basic` over an unhandled bearer; other requests prefer the
unhandled bearer. Unmatched handled credentials are the last fallback. Ties
within a rank retain the existing first-match behavior. A sole Basic credential
also applies to requests with no Authorization header or with a Bearer placeholder.
When no credential matches, caller-supplied Authorization and API-key headers
pass through unchanged. Forged session attribution still strips those headers
and never injects vault credentials; networking policy is enforced in every case.

List/get responses include the username and URL but omit `token`. Rotate with
`POST /v1/vaults/:id/credentials/:credential_id` and
`{"auth":{"type":"static_basic","token":"NEW_SECRET_KEY"}}`; delete through
the same resource with `DELETE`. A null token disables injection until rotated.
Basic credentials never refresh on 401. The console offers **HTTP Basic** with
username/password inputs and password rotation.

Use the native credentials API for this OMA extension. The upstream OpenAI SDK
contract does not include it, so OpenAI credential lists omit it. Shared MCP
forwarders support Basic, but Cloudflare's bearer-only outbound credential lookup
explicitly rejects it. See the [self-host Langfuse example](/self-host/node-docker/#langfuse-with-http-basic).

### Service account JWT credentials

`service_account_jwt` exchanges an RS256-signed assertion for a short-lived
Bearer token using the RFC 7523 JWT bearer grant. Google service accounts are
the first supported recipe; no user consent or personal refresh token is needed.
Use the native `/v1/vaults/:id/credentials` API. The OpenAI compatibility API
omits this extension from its credential lists.

| Auth field | Meaning |
|---|---|
| `mcp_server_url` | Required HTTP(S) host binding, including a nondefault port |
| `client_email` | Required issuer (`iss`) |
| `private_key` | Required RSA private key PEM; encrypted and never returned |
| `private_key_id` | Optional JWT header `kid` |
| `token_uri` | HTTPS token endpoint; defaults to `https://oauth2.googleapis.com/token` |
| `scopes` | Required space-separated scope string; JWT `scope` |
| `subject` | Optional JWT `sub`, for administrator-authorized domain-wide delegation |
| `audience` | Optional JWT `aud`; defaults to `token_uri` |
| `key_json` | Input-only Google JSON key, as an object or JSON string; supplies `client_email`, `private_key`, `private_key_id`, and `token_uri` |

Supply `scopes` alongside `key_json`. List/get responses expose public metadata,
including the issuer, scopes, token endpoint and configured subject, but omit
`private_key`, `key_json` and minted access tokens. The console accepts a pasted
JSON key and shows a masked key after saving.

Google service accounts have no Drive storage of their own (quota **0**). Add
the service account to a **shared drive** as **Content manager**, and create
files there or in a folder inside it. Creation elsewhere fails with a
`storageQuotaExceeded` quota error.

Update non-secret fields using `POST /v1/vaults/:id/credentials/:credential_id`:

```json
{
  "auth": {
    "type": "service_account_jwt",
    "mcp_server_url": "https://www.googleapis.com/",
    "scopes": "https://www.googleapis.com/auth/drive https://www.googleapis.com/auth/documents",
    "subject": "delegated-user@example.com"
  }
}
```

Omit `subject` for direct service-account access. Rotate with the same endpoint
and `auth: { type: "service_account_jwt", key_json: NEW_KEY_OBJECT }`, or supply
`private_key` and `private_key_id` directly. Delete with `DELETE` on the same
resource. Key or authentication metadata changes invalidate cached tokens.

Self-host `oma-vault` mints on first use and renews within five minutes of
expiry. Concurrent requests share one mint per credential/revision in a
process. Tokens and expiry are persisted in encrypted credential storage using
a revision check so other processes can reuse them; this is not a distributed
mint lock. When processes race, the loser uses the persisted winner's token;
a restart reuses that token until renewal is due. A rejected upstream token
(401) triggers at most one re-mint and
retry. Token requests have a bounded timeout and do not follow redirects.
Cloudflare forwarding explicitly rejects this kind; use self-host `oma-vault`.

This kind has the same rank as a handle-less `static_bearer`. Exact bearer/CLI
handle matches win first. Basic callers then prefer `static_basic`; other
callers prefer handle-less bearers. A service account and a `static_bearer` on
the same host tie: the first credential in the existing vault/store traversal
wins. Avoid ambiguous bindings by attaching only the intended credential for
that host. See the [Google Drive and Docs recipe](/build/vault-and-mcp/#google-drive-and-docs-with-a-service-account).

### Codex / ChatGPT subscription credentials

<Aside type="caution" title="Local debugging only — high risk">
  A Codex or ChatGPT subscription login is a local direct-host convenience, not
  a production model integration. Provider terms, rate limits, and security
  checks can restrict or suspend an account. Keep this path to local debugging
  on a trusted machine only.
</Aside>

**Current status:** Model Cards currently accept static API-key credentials.
Codex/ChatGPT subscription OAuth is a direct-host adapter contract for local
debugging; it is not a hosted Model Card or a remote-sandbox credential type.

When that direct-host adapter is enabled, it keeps the provider OAuth credential
in the host's local Pi-compatible credentials store. It must never copy
`~/.codex/auth.json`, a refresh token, or an access token into a sandbox,
workspace checkpoint, output archive, Model Card, or request payload. The
sandbox receives no subscription credential and cannot refresh it.

For a remote or managed sandbox, configure an approved API key or provider
OAuth credential behind the OMA model gateway instead. The gateway is the
credential boundary: it authenticates the request, applies the tenant/model
policy, and returns only the model response to the sandbox. This preserves the
same harness endpoint shape without turning a subscription login into a
portable secret.

These paths are intentionally distinct:

| Path | Credential location | Intended use |
|---|---|---|
| Local `direct-host` | Trusted host Pi credentials store | Local debugging only |
| Remote/managed sandbox | OMA model gateway; approved API/OAuth credential stays in the control plane | Production/managed execution |

Do not treat the local credential file as a portable session artifact. If it is
missing after a runtime replacement, resume the ACP/native session from its
declared session state and require the user to authenticate again on the trusted
host; do not reconstruct or transmit the subscription token from Session events.

## Skill

```ts
interface SkillMetadata {
  type: 'skill';
  id: string;
  display_title: string;
  name: string;                  // SKILL.md frontmatter `name` — also the mount-folder name
  description: string;
  source: 'anthropic' | 'custom';
  latest_version: string;        // numeric epoch string
  created_at: string;
  updated_at: string;
}

// Per-version detail returned by GET /v1/skills/:id/versions/:version
interface SkillVersion {
  version: string;
  files: Array<{ filename: string }>;  // R2 objects under t/{tenant}/skills/{id}/{version}/<filename>
}
```

The platform mounts skill files at `/home/user/.skills/{name}/` (using the SKILL.md `name`, not `id`) and **inlines the SKILL.md body directly into the system prompt** at session start — no lazy read. The injected wrapping is:

```text
<source name="skill:{id}">
<skill name="{name}">
{full SKILL.md body}
</skill>
</source>
```

Attach to an agent with the object form (not a bare string array):

```json
{ "skills": [{ "skill_id": "skill_abc123", "type": "custom" }] }
```

Built-in skills (`source: "anthropic"`): `xlsx`, `pdf`, `docx`, `pptx` — four total, no upload needed.

### Node rate limits

These settings apply to `apps/main-node` only and are parsed once at boot.
Each accepts a positive safe integer count per minute; `0` or `off` disables
that gate (unlimited). Invalid values produce a startup warning and retain
the default. Restart the process after changing them. Startup logs include
the effective `apiWrite` and `sessionsTenant` limits.

| Variable | Default per minute | Scope |
|---|---|---|
| `OMA_RATE_LIMIT_API_WRITES_PER_MINUTE` | `60` | `/v1/*` POST, PUT and DELETE requests per authenticated principal (API key, user, or fallback IP) |
| `OMA_RATE_LIMIT_SESSIONS_PER_TENANT_PER_MINUTE` | `30` | Legacy session creation per tenant on `/v1/oma/sessions` |
| `OMA_RATE_LIMIT_AUTH_IP_PER_MINUTE` | `60` | `/auth/*` requests per IP |
| `OMA_RATE_LIMIT_AUTH_SEND_IP_PER_MINUTE` | `10` | Email-triggering auth requests per IP |
| `OMA_RATE_LIMIT_AUTH_SEND_EMAIL_PER_MINUTE` | `3` | Email-triggering auth requests per email address |

For a single-tenant member portal and probes sharing one API key, start with
`OMA_RATE_LIMIT_API_WRITES_PER_MINUTE=600`. A transform start costs about
33 `/v1/*` writes: an agent, a session, 12 topic-video parts with two calls
each, three guidance files, and the first message. Retirement costs about
20 more writes. Two starts within a minute cost about 66 writes, exceeding
the default 60 and causing a 429 partway through staging. Leave the auth
limits at their defaults unless your usage requires an override.

Reads do not consume the write budget. Managed session creation on
`/v1/sessions` consumes only the write budget. Legacy session creation on
`/v1/oma/sessions` consumes both the write budget and its separate tenant
budget; admission precedes body validation. Write, legacy session, and auth
limit 429 responses retain their JSON error body and include `Retry-After`
in seconds until the bucket refills.
These limits are in memory per Node process; multiple replicas require a
shared limiter backend. Cloudflare bindings and limits are unchanged.
